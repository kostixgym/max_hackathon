# ОСС в MAX

Готовый чат-бот и мини-приложение для организации общих собраний собственников многоквартирного дома. Проект команды **Hulk Founder** для трека **«Умный город»** хакатона MAX.

[Открыть бота в MAX](https://max.ru/t603_hakaton_max_bot) · [Открыть мини-приложение](https://45-154-58-251.sslip.io/)

## Статус

Решение полностью готово и развёрнуто. Реализован сквозной сценарий от привязки квартиры и инициативы жителя до проведения собрания, фиксации результата и формирования PDF-протокола.

Сценарий проверен автоматически на изолированном стенде с десятью пользователями: 9 голосов «за», 1 «против», достижение порога 10%, требование в УК, собрание, обработка 75 бюллетеней, фиксация результата и генерация протокола. Бот и мини-приложение также открываются в настоящем MAX.

## Задача

Инициатору общего собрания приходится самостоятельно формулировать повестку, собирать поддержку, учитывать площади и доли собственников, взаимодействовать с УК, принимать бюллетени и готовить документы. ОСС в MAX объединяет весь процесс:

1. Житель выбирает дом и подтверждает квартиру.
2. Создаёт инициативу по готовому шаблону.
3. Соседи участвуют в предварительном опросе в MAX.
4. Система считает поддержку в м² и показывает пороги 10%, кворума и 2/3.
5. Инициатор формирует требование провести собрание.
6. Сотрудник УК создаёт собрание и ведёт трекер квартир.
7. УК принимает бумажные бюллетени и вносит решения.
8. Система объединяет бумажные результаты с агрегатами ГИС ЖКХ, фиксирует итог и формирует PDF-протокол.

Предварительный опрос помогает оценить поддержку инициативы. Он не заменяет юридически значимое голосование на бумаге или в государственной информационной системе.

## Возможности

- бот MAX: запуск приложения, голосование кнопками, вопросы инициатору, уведомления и команда `/id`;
- привязка пользователя к дому и квартире;
- профиль жителя и несколько квартир на одном аккаунте;
- шаблоны инициатив с проверкой полей и автоматической повесткой;
- подсчёт голосов по площади и доле собственности;
- прогресс относительно порогов 10%, кворума и 2/3;
- требование в УК, срок ответа и PDF требования;
- режимы жителя, сотрудника УК и системного администратора;
- назначение ролей УК по MAX ID без перезапуска;
- создание собрания, выбор председателя и секретаря;
- трекер квартир, список обхода и приём бюллетеней;
- внесение решений по каждому вопросу;
- ручной ввод официальных агрегатов ГИС ЖКХ;
- предпросмотр и однократная фиксация результата;
- PDF-протокол собрания;
- демо-ускорители для прохождения сценария без ожидания календарных сроков;

## Проверка в MAX

1. Откройте [@t603_hakaton_max_bot](https://max.ru/t603_hakaton_max_bot).
2. Запустите мини-приложение из диалога.
3. Выберите демо-дом: **г. Казань, ул. Демонстрационная, д. 1**.
4. Привяжите свободную квартиру.
5. Создайте инициативу «Видеонаблюдение» и запустите опрос.
6. Проголосуйте и откройте прогресс.

Демо-дом содержит 60 квартир и коммерческое помещение общей площадью 3 000 м².

| Порог | Площадь |
|---|---:|
| Требование в УК, 10% | 300 м² |
| Кворум | больше 1 500 м² |
| Решение, требующее 2/3 | 2 000 м² |

Для полного сценария нужны несколько участников, чтобы набрать 300 м². Роль сотрудника УК выдаёт системный администратор по MAX ID. Свой ID пользователь получает командой `/id` в личном диалоге с ботом. Все данные демо-дома синтетические.

## Архитектура

```text
Клиент MAX
  ├── чат с ботом ───────────────┐
  └── React-мини-приложение ──┐  │
                              ▼  ▼
                         Caddy / HTTPS
                              │
                         Go API + бот
                              │
                         PostgreSQL 18
```

| Каталог | Назначение |
|---|---|
| `frontend/` | React 19, TypeScript, MAX UI, интерфейсы жителя, УК и администратора |
| `backend/` | Go 1.27, Gin, бизнес-логика, MAX Bot API, PDF и фоновые задачи |
| `deploy/` | Caddy и production-сборка frontend |
| `compose.yaml` | PostgreSQL, backend и web одной командой |

Бэкенд собран как модульный монолит. Миграции goose встроены в бинарник и применяются при запуске. PostgreSQL доступен только внутри compose-сети, а frontend и API публикуются через Caddy.

## Локальный запуск

Понадобятся Docker 24+ и Docker Compose v2.24+.

```bash
cp .env.example .env
```

Для запуска без MAX задайте:

```dotenv
POSTGRES_PASSWORD=local-database-password
HMAC_SECRET=replace-with-at-least-32-random-bytes
DEV_MODE=true
MAX_BOT_TOKEN=
VITE_DEV_USER_ID=1001
VITE_DEV_START_PARAM=demoLocalHouse01
DEMO_INVITE_SLUG=demoLocalHouse01
```

Случайный HMAC-ключ:

```bash
openssl rand -hex 32
```

Запуск:

```bash
docker compose up --build -d
```

После запуска доступны:

- приложение: <http://localhost:8080>;
- health check: <http://localhost:8080/api/v1/healthz>;
- readiness check: <http://localhost:8080/api/v1/readyz>;
- журналы: `docker compose logs -f app`.

`DEV_MODE=true` используется только локально. Frontend передаёт тестовый `X-Dev-User-Id`, а бот MAX не запускается.

## Запуск с MAX

Для production задайте:

```dotenv
DEV_MODE=false
MAX_BOT_TOKEN=<токен бота>
HMAC_SECRET=<случайный секрет длиной не менее 32 байт>
SITE_ADDRESS=example.org
HTTP_PORT=80
HTTPS_PORT=443
```

```bash
docker compose up --build -d
```

HTTPS-адрес указывается как URL мини-приложения в настройках бота на платформе MAX. Один токен используется одним запущенным экземпляром, поскольку бот получает события через long polling.

Секреты хранятся только в `.env` или секретах окружения. Не добавляйте `.env`, токен MAX, пароль PostgreSQL и HMAC-ключ в Git.

## Переменные окружения

Полный шаблон находится в [.env.example](.env.example).

| Переменная | Назначение |
|---|---|
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `MAX_BOT_TOKEN` | Токен бота, обязателен при `DEV_MODE=false` |
| `HMAC_SECRET` | HMAC-ключ для телефонов и лицевых счетов |
| `DEV_MODE` | Локальная авторизация через `X-Dev-User-Id` |
| `INITDATA_MAX_AGE` | Максимальный возраст подписанного запуска MAX |
| `VITE_DEV_USER_ID` | Тестовый пользователь локального frontend |
| `VITE_DEV_START_PARAM` | Slug дома для локального frontend |
| `SEED_DEMO` | Создание демо-дома |
| `DEMO_INVITE_SLUG` | Постоянный slug демо-дома |
| `QUIET_HOURS` | Отложенная отправка уведомлений ночью |
| `SITE_ADDRESS` | Домен Caddy или `:80` для локального HTTP |
| `HTTP_PORT`, `HTTPS_PORT` | Публичные порты web-контейнера |
| `LOG_LEVEL` | Уровень журналирования |

## Роли

- **Житель** — квартиры, инициативы, опросы и требования.
- **УК** — дома организации, требования и собрания.
- **Администратор** — назначение и отзыв ролей сотрудников УК.

Первый системный администратор добавляется один раз. Пользователь отправляет боту `/id`, затем на сервере выполняется:

```sql
BEGIN;
INSERT INTO users (max_user_id)
VALUES (123456789)
ON CONFLICT (max_user_id) DO NOTHING;

INSERT INTO system_admins (user_id)
SELECT id FROM users WHERE max_user_id = 123456789
ON CONFLICT (user_id) DO NOTHING;
COMMIT;
```

Дальше роли меняются в панели администратора или командами:

```text
/admin orgs
/admin users <часть_MAX_ID>
/admin grant <MAX_ID> <ORG_ID> <operator|admin>
/admin revoke <MAX_ID> <ORG_ID>
```

## Безопасность данных

- production API проверяет подписанный `initData` MAX;
- запуск с истёкшим `auth_date` отклоняется;
- телефоны и лицевые счета хранятся как HMAC-SHA256;
- ФИО собственников передаются в маскированном виде;
- доступ ограничивается членством в доме и ролью организации;
- площади считаются в целых сотых м², доли — рациональными числами;
- итог собрания фиксируется один раз;
- база данных не публикуется наружу;
- демо не содержит персональных данных реальных людей.

## Интеграции и ограничения

| Система | Состояние |
|---|---|
| MAX Bot API и мини-приложение | Работают в production |
| ГИС ЖКХ / Госуслуги.Дом | Прямой интеграции нет; реализован ручной ввод официальных агрегатов |
| Реестр и биллинг УК | В демо используются синтетические данные |
| ФИАС | Адрес хранится структурированно, внешний автокомплит не подключён |

Официальный голос отдаётся на бумаге или в государственной системе. Приложение организует процесс, показывает прогресс, помогает перенести результаты и формирует документы.
