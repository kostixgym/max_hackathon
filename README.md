# Инициативы жителей в MAX (рабочее название)

Хакатон MAX, трек «Умный город». Чат-бот и мини-приложение в MAX.

> **Статус: этап 1 — сквозной сценарий, в работе.** Работают:
> - запуск одной командой;
> - бот: `/start`, вход по ссылке дома, опрос с кнопками голосования;
> - HTTP API с проверкой запуска из MAX;
> - синтетический демо-дом;
> - инициатива по шаблону, опрос поддержки в м², очередь рассылок.
>
> Требование в УК, собрание и протокол — следующие шаги этапа 1. Мини-приложение пока заглушка.
> План и журнал: [docs/05-plan-realizacii.md](docs/05-plan-realizacii.md), [docs/completed/](docs/completed/README.md).

## Назначение

Собственник квартиры хочет улучшить дом: поставить камеры, заменить домофон, отремонтировать подъезд. Для этого нужно решение
общего собрания собственников, а инициатор обычно не знает правил, обходит все квартиры и считает голоса вручную.

Приложение ведёт инициатора по всему пути: правильная формулировка вопроса и пороги голосования, опрос поддержки соседей в чате,
требование в УК провести собрание, учёт бюллетеней по квартирам, подсчёт по площади и черновик протокола.
**Юридически значимый голос приложение не подменяет:** его собственник отдаёт в Госуслуги.Дом или на бумажном бюллетене.
Подробно — [docs/02-koncepciya-produkta.md](docs/02-koncepciya-produkta.md).

## Основной пользовательский сценарий

1. Житель открывает ссылку своего дома (QR на подъезде, домовой чат MAX) и подтверждает, что он собственник.
2. Инициатор выбирает шаблон («Видеонаблюдение», «Домофон»…) и видит, сколько голосов нужно: 10% / кворум / 2/3 от площади дома.
3. Собственники получают опрос в чате и голосуют кнопками; прогресс считается в м².
4. Набрав 10%, инициатор отправляет в УК требование провести собрание (ст. 45 ч. 6 ЖК) — или проводит его сам.
5. Во время собрания приложение отмечает, кто проголосовал онлайн или сдал бумажный бюллетень, и напоминает остальным.
6. Итог по каждому вопросу фиксируется один раз, из него строится протокол.

**Сейчас реализованы шаги 1–3.** Вход по ссылке дома в боте и API. Демо-подтверждение собственника. Инициатива по шаблону
«Видеонаблюдение» с порогами. Опрос поддержки: приглашение в чат, голос кнопками или из мини-приложения, прогресс в м².
Шаги 4–6 — дальше в этапе 1.

## Состав и архитектура

Модульный монолит: один сервис на Go, одна база PostgreSQL, Caddy как единственный вход.

```
 Клиент MAX (мобильный / веб)
   │ чат с ботом              │ мини-приложение (HTTPS)
   ▼                          ▼
 MAX Bot API            ┌───────────────┐
   ▲ long polling       │ web: Caddy     │  статика мини-приложения, /api/* → app, TLS на сервере
   │                    └───────┬───────┘
   │                    ┌───────▼───────┐
   └────────────────────┤ app: Go        │  HTTP API /api/v1, бот, миграции при старте, демо-дом
                        └───────┬───────┘
                        ┌───────▼───────┐
                        │ db: PostgreSQL │  18, данные только внутри сети compose
                        └───────────────┘
```

| Сервис | Что внутри |
|---|---|
| `web` | Caddy 2: раздаёт мини-приложение и проксирует `/api/*` в `app`. **До шага 0.4 вместо мини-приложения — страница-заглушка** |
| `app` | Go 1.27, один бинарник: HTTP API (Gin), бот MAX (long polling), встроенные миграции goose, сид демо-дома |
| `db` | PostgreSQL 18 |

Модули и модель данных — [docs/04-model-dannyh.md](docs/04-model-dannyh.md), схемы — `docs/03-arhitektura.drawio`.

## Запуск одной командой

```bash
cp .env.example .env     # один раз: заполнить MAX_BOT_TOKEN и HMAC_SECRET (openssl rand -hex 32)
docker compose up --build
```

- Мини-приложение (пока заглушка): <http://localhost:8080>
- API: <http://localhost:8080/api/v1/healthz>

**Без токена MAX** поставьте в `.env` `DEV_MODE=true`: бот выключится, а API будет принимать запросы с заголовком `X-Dev-User-Id`
вместо подписи MAX. Только для локального запуска.

**Токен бота** — только в `.env`, строкой `MAX_BOT_TOKEN=<токен>`. Файл `.env` в `.gitignore`, в коммит он не попадёт.
Токен не пишите ни в `.env.example`, ни в код, ни в чаты. С токеном локально работает весь бот: long polling не требует
публичного адреса. Публичный HTTPS-адрес нужен только мини-приложению.

## Переменные окружения

Все — в `.env` (шаблон `.env.example`). В репозитории секретов нет.

| Переменная | По умолчанию | Обязательна | Назначение |
|---|---|---|---|
| `POSTGRES_PASSWORD` | — | да | пароль пользователя БД `app`; compose собирает из него `DATABASE_URL` |
| `MAX_BOT_TOKEN` | — | да, если `DEV_MODE=false` | токен бота от организаторов |
| `HMAC_SECRET` | — | да | ключ HMAC для телефонов и лицевых счетов, ≥ 32 байт |
| `DEV_MODE` | `false` | нет | `true` — запросы без подписи MAX (`X-Dev-User-Id`). **Никогда на сервере** |
| `INITDATA_MAX_AGE` | `24h` | нет | сколько действителен запуск мини-приложения |
| `SEED_DEMO` | `true` | нет | создать демо-дом при первом старте |
| `DEMO_INVITE_SLUG` | случайный | нет | постоянная ссылка демо-дома, `[A-Za-z0-9_-]` |
| `SITE_ADDRESS` | `:80` | нет | `:80` — локально по HTTP; домен — на сервере, Caddy получит HTTPS сам |
| `HTTP_PORT` / `HTTPS_PORT` | `8080` / `8443` | нет | порты на хосте; на сервере — `80` / `443` |
| `LOG_LEVEL` | `info` | нет | `debug` / `info` / `warn` / `error` |
| `DATABASE_URL`, `HTTP_ADDR` | — | — | только для запуска без Docker (`go run`); в compose задаются автоматически |

## Порты

| Порт | Где | Назначение |
|---|---|---|
| `8080` (хост) → `web:80` | снаружи | HTTP: мини-приложение и API |
| `8443` (хост) → `web:443` | снаружи | HTTPS, когда `SITE_ADDRESS` — домен |
| `app:8080` | внутри сети compose | API, доступен только через `web` |
| `db:5432` | внутри сети compose | PostgreSQL, наружу не публикуется |

## Зависимости

- **Для запуска:** Docker 24+ и Docker Compose v2.24+.
- **Для разработки:** Go 1.27.1 (с шага 0.4 — Node.js 22).
- **Библиотеки** (версии зафиксированы в `backend/go.mod` и `backend/go.sum`): официальный клиент MAX `max-bot-api-client-go/v2`, `gin`, `pgx/v5`, `goose/v3`.

## Внешние сервисы и интеграции

| Сервис | Зачем | Статус |
|---|---|---|
| **MAX Bot API** (`platform-api2.max.ru`) | бот: события и сообщения | работает при заданном `MAX_BOT_TOKEN`. **В Docker не воспроизводится:** нужен токен, а для мини-приложения — адрес по HTTPS в настройках бота на платформе MAX («Чат-боты → Настройки») |
| Госуслуги.Дом / ГИС ЖКХ | законное онлайн-голосование собрания | **модельно:** интеграции нет, в MVP — переход по ссылке и ручной ввод итогов (этап 1) |
| Данные УК (реестр собственников, биллинг) | площади, доли, подтверждение собственника | **модельно:** синтетический демо-дом |

**Сертификат API MAX выпущен национальным УЦ Минцифры** (Russian Trusted Root CA). Этого корня нет в стандартных хранилищах
сертификатов. Бэкенд несёт его в себе (`backend/internal/platform/maxbot/certs`, источник и отпечаток — в `tls.go`) и доверяет
ему только в запросах к MAX. Без него бот падает с `x509: certificate signed by unknown authority`.

**Один токен — один получатель событий.** Если бот с этим же токеном уже запущен на сервере, локальный запуск будет перехватывать
его события. Для локальной проверки используйте `DEV_MODE=true` без токена или остановите сервер.

## Работа с данными

- PostgreSQL 18. Миграции встроены в бинарник и применяются при старте (goose, блокировка от параллельного запуска).
- Площади хранятся в целых сотых м², доли — дробью; голоса считаются точно, округление только при показе.
- Телефоны и лицевые счета — только HMAC-SHA256 с серверным секретом; ФИО собственников отдаются только с маской и только тем, кому они нужны.
- Рассылки идут через очередь задач в PostgreSQL. Выполненные задачи, а в них MAX id получателя, удаляются через 30 дней.
- Все данные в MVP синтетические. Политика хранения и остальные решения — [docs/04-model-dannyh.md](docs/04-model-dannyh.md).

## Тестовые данные

**Демо-дом** создаётся при первом старте (`SEED_DEMO=true`): г. Казань, ул. Демонстрационная, д. 1 — 60 квартир и магазин,
ровно **3 000 м²**, поэтому пороги: 10% = 300 м², кворум — больше 1 500 м², 2/3 = 2 000 м². Есть совместная собственность
(1/2, 1/3) и муниципальная квартира. Все имена, телефоны и лицевые счета выдуманы.

- Ссылка на дом — значение `DEMO_INVITE_SLUG` (или из журнала: `docker compose logs app | grep "demo house ready"`):
  - мини-приложение: `https://max.ru/<ник_бота>?startapp=<slug>`;
  - бот: `https://max.ru/<ник_бота>?start=<slug>`.
- **Стать собственником в демо-доме** можно одним запросом: `POST /api/v1/houses/<slug>/demo-membership` с номером квартиры.
  В квартирах с совместной собственностью нужно ещё поле `owner_index`: в кв. 43 два собственника по 1/2, в кв. 7 — три по 1/3.
  Пары «лицевой счёт + сумма» для обычного подтверждения появятся позже.
- **Опрос в демо-доме уходит только его инициатору.** Все тестировщики — собственники одного дома, и без этого правила каждый
  получал бы чужие опросы.
- Сбросить данные: `docker compose down -v` — при следующем старте демо-дом создастся заново.

## Пошаговая проверка

**A. Локально, без MAX** (`DEV_MODE=true` в `.env`, `DEMO_INVITE_SLUG=demoLocalHouse01`):

```bash
docker compose up --build -d
curl -s localhost:8080/api/v1/healthz        # {"status":"ok"}
curl -s localhost:8080/api/v1/readyz         # {"status":"ready"}
curl -s localhost:8080/api/v1/me             # 401: {"error":{"code":"unauthorized",...}}
curl -s -H "X-Dev-User-Id: 1001" -H "X-Dev-Start-Param: demoLocalHouse01" localhost:8080/api/v1/me
```

Опрос поддержки целиком: собственник, инициатива, опрос, голос, прогресс. `house.id` берётся из ответа `/me`:

```bash
H='X-Dev-User-Id: 1001'; J='Content-Type: application/json'; API=localhost:8080/api/v1
curl -s -X POST $API/houses/demoLocalHouse01/demo-membership -H "$H" -H "$J" -d '{"premise_number":"12"}'
HOUSE=<house.id из /me>
curl -s -X POST $API/houses/$HOUSE/initiatives -H "$H" -H "$J" \
     -d '{"template_code":"video_surveillance","title":"Камеры в подъездах"}'           # 201, повестка из 2 вопросов
ID=<id из ответа>
curl -s -X POST $API/initiatives/$ID/start-poll -H "$H" -H "$J" -d '{}'              # опрос на 7 дней
curl -s -X PUT  $API/initiatives/$ID/my-vote    -H "$H" -H "$J" -d '{"choice":"for"}' # {"weight_m2":"63.50",...}
curl -s $API/initiatives/$ID/poll -H "$H"                                            # {"for_m2":"63.50","demand_m2":"300.00",...}
```

**B. В MAX** (заданный `MAX_BOT_TOKEN`; для мини-приложения ещё сервер с доменом в `SITE_ADDRESS` и его адрес в настройках бота):

1. Откройте диалог с ботом и нажмите «Начать» → приветствие и кнопка «Открыть приложение».
2. Перейдите по `https://max.ru/<ник_бота>?start=<slug>` → приветствие с адресом демо-дома и пометкой «данные синтетические».
3. Нажмите «Открыть приложение» → откроется мини-приложение (до шага 0.4 — заглушка), дом передаётся в него через `start_param`.
4. Когда собственник квартиры запускает опрос, бот присылает сообщение с кнопками «Поддерживаю / Против / Есть вопрос».
   После нажатия сообщение обновляется: в нём ваш голос в м², а изменить его можно до конца опроса.
   В тихие часы (22:00–9:00 по времени дома) рассылка ждёт утра.

**C. Автотесты:**

```bash
cd backend && go test ./...                                   # без БД интеграционные тесты пропускаются
docker run --rm -d --name pg-test -e POSTGRES_PASSWORD=test -p 55432:5432 postgres:18-alpine
TEST_DATABASE_URL='postgres://postgres:test@localhost:55432/postgres?sslmode=disable' go test ./... -count=1
```

CI (`.github/workflows/ci.yml`) запускается на каждый пуш в любую ветку. Он проверяет `gofmt` и `go vet`, прогоняет все тесты
с `-race` на PostgreSQL 18 и собирает образы с лимитом 5 минут.

## Примеры ожидаемого поведения

`GET /api/v1/me` по ссылке демо-дома:

```json
{
  "user": {"id": "01a0…", "first_name": "Анна"},
  "dev_mode": false,
  "house": {
    "slug": "demoLocalHouse01", "address": "г. Казань, ул. Демонстрационная, д. 1 (демо-дом)",
    "is_demo": true, "premises_count": 61, "registry_version": 1, "total_area_m2": "3000.00",
    "thresholds": {"demand_m2": "300.00", "quorum_above_m2": "1500.00", "two_thirds_m2": "2000.00"}
  },
  "memberships": []
}
```

`GET /api/v1/initiatives/{id}/poll` — прогресс опроса в м² от площади снимка реестра:

```json
{"for_m2": "63.50", "against_m2": "0.00", "total_m2": "3000.00", "demand_m2": "300.00", "demand_reached": false,
 "poll_ends_at": "2026-10-03T18:00:00+03:00", "for_percent": "2.1", "votes_for": 1, "votes_against": 0}
```

- Запрос без подписи MAX → `401 unauthorized`; устаревший запуск → `401 init_data_expired`; неизвестный дом → `404 house_not_found`.
- Голос не собственника → `403 not_owner`, голос после опроса → `409 poll_closed`, второй аккаунт на одну запись
  собственника → `409 owner_taken`, больше 10 инициатив за сутки → `429 too_many_initiatives`.
- Ошибки API всегда в одном формате: `{"error": {"code": "…", "message": "текст для пользователя"}}`.
- Полное описание API — [docs/API_DESCRIPTION.md](docs/API_DESCRIPTION.md).

## Известные ограничения

- Мини-приложение — заглушка до шага 0.4. Требование в УК, собрание и протокол — следующие шаги этапа 1.
- В API пока нет списка шаблонов, списка инициатив дома и карточки инициативы. Они есть в контракте
  ([docs/API_DESCRIPTION.md](docs/API_DESCRIPTION.md)) и появятся вместе с экранами.
- Интеграции с Госуслуги.Дом, ГИС ЖКХ и данными УК модельные, данные синтетические.
- Работа в настоящем MAX не проверена (шаг 0.6, нужен токен). Подпись запуска с именами, содержащими `+` или `%`, требует проверки на реальных аккаунтах.
- Бот работает через long polling: одна копия на токен. Для нескольких копий нужен webhook (план роста, docs/05).
- Собственный API не заявляется: бэкенд — внутренняя часть решения.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, всё сохраняется
docker compose start           # запустить снова
docker compose down            # удалить контейнеры, данные в томах сохраняются
docker compose down -v         # удалить и данные (демо-дом создастся заново)
docker compose up --build -d   # пересобрать после изменений кода
docker compose logs -f app     # журнал сервиса (JSON)
```
