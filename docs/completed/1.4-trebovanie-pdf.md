# Шаг 1.4. Требование в УК: модуль demand, порог 10%, PDF

Дата: 27.09.2026. Статус: готово, ждёт ревью. Ветка: `feat/sprint-skeleton` (некоммиченные правки —
в рабочем каталоге; коммитит Костя).

Цель шага — замкнуть середину сценария: после опроса инициатор одним вызовом создаёт требование в УК
(ст. 45 ч. 6 ЖК), скачивает его PDF, отмечает передачу — и стартует 45-дневный срок УК.

## Что сделано

```
backend/
  internal/demand/                      модуль «Требование в УК» (владелец таблицы demands)
    demand.go                           Create / Get / MarkDelivered / ListByHouses / PDF
    demand_integration_test.go          интеграционный тест флоу
  internal/documents/
    demand_pdf.go                       чистая функция DemandPDF(data) → PDF-байты
    font.go + assets/DejaVuSans.ttf     шрифт с кириллицей встроен в бинарник
  internal/platform/httpapi/demands.go  4 ручки вместо заглушек
  migrations/20260927150000_demand_house_id.sql   денормализация house_id
```

### Модуль demand (Д1)

- **`POST /initiatives/{id}/demand`** — только инициатор, только на стадии `poll`, только при поддержке
  **не меньше 10%** («не менее» — граница покрыта тестами `rules`). Одна транзакция: строка `demands`
  с зафиксированной поддержкой (точная дробь из снимка опроса) + `SetStageTx(poll → demand, path A)`.
  Гонка двух создателей закрывается стадией: проигравший получает `409 demand_exists`.
- **`GET /demands/{id}`** — инициатор и сотрудник УК, который ведёт инициативу (через `access.ManagesAsStaff`).
  `overdue` считается при чтении: срок 45 дней прошёл, а собрания нет.
- **`POST /demands/{id}/mark-delivered`** — только инициатор, один раз (`409 already_delivered`);
  с этого момента `uk_due_at` = +45 дней.
- Ошибки домена различимы и замаплены: `not_initiator`, `support_not_reached`, `demand_exists`,
  `wrong_stage`, `already_delivered`, `forbidden`.

### PDF (Д2–Д3)

- `documents.DemandPDF(data)` — чистая функция: данные → PDF-байты. Шрифт DejaVu Sans (свободная
  лицензия) встроен через `go:embed`, поэтому кириллица работает и в distroless-образе.
- Документ: адресат (УК), дом, требование по ч. 2 ст. 45 ЖК, повестка, поддержка в м² против порога 10%,
  инициатор и помещение, форма собрания, **пустая таблица подписей без ФИО** (решение 20), дата.
- `GET /demands/{id}/pdf` — инициатор и сотрудники УК, `Content-Disposition: inline`.

### Кабинет УК (К2-хвост)

- `GET /orgs/{orgID}/demands` — требования домов организации: каналы, статусы, поддержка, сроки,
  просрочка, заголовки инициатив и адреса домов. Доступ — только сотрудник этой организации (`403 not_staff`).

## Решения и почему

| Решение | Почему |
|---|---|
| **`house_id` денормализован в `demands`** (миграция) | Кабинету УК нужен список требований по домам; JOIN на таблицу инициатив нарушил бы границы модулей (поймал ownership-тест). Бэкфилл одной миграцией |
| **Поддержка фиксируется дробью на момент создания** | Требование ссылается на достигнутую поддержку честно: рост опроса после создания не «улучшает» задним числом документ |
| **`SetStageTx` проверяет `from` и матрицу переходов** | Гонка двух создателей требования → `409 demand_exists` у проигравшего; случайный переход в неположенную сторону невозможен |
| **Прогресс читается до транзакции** | Модули читают данные через пул до начала транзакции: соединение внутри транзакции ждёт второе соединение — классический дедлок пула (замечание из отчёта 1.3) |
| **DejaVu Sans через `go:embed`** | Кириллица в PDF без системных шрифтов — работает в distroless-образе |
| **PDF видят инициатор и УК** | Сотруднику не нужен: он получает требование из кабинета списком (К2) |

## Как проверено

```
gofmt, go vet, все тесты с -race на PostgreSQL 18 (-p 1: интеграционные делят демо-базу) — зелёные
```

Интеграционный тест флоу (`demand_integration_test.go`): пять собственников больших квартир,
4 голоса = 254 м² (ниже порога → `ErrSupportNotReached`), 5-й голос → 317,50 м² → требование создаётся,
`support = 31750/1` сотых м², повторное — `ErrExists`, передача не инициатором — `ErrNotInitiator`,
повторная передача — `ErrAlreadyDelivered`, `uk_due_at` = +45 дней, PDF > 2 КБ с `%PDF`, просрочка при чтении,
чужой пользователь — `ErrForbidden`. Плюс стадия `demand` и путь `A` после требования.

## Что не сделано

- Уведомления бота по джобам `demand_delivered` / `meeting_created` / `meeting_finalized` — с К3 (Костя).
- `ListByHouses` для кабинета отдаёт id инициатив; заголовки подтягивает хендлер `/orgs/{orgID}/demands`.
- `overdue` не ставит джобу напоминания — флаг читается в кабинете (по плану рассылка о просрочке ушла
  в «известные ограничения»).
- Жалоба в жилищную инспекцию при просрочке — этап 2.
