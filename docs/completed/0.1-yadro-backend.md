# Шаг 0.1. Каркас бэкенда

Дата: 25.09.2026. Статус: готово, ждёт ревью.

Цель шага — заложить фундамент без сети и без бота: конфигурацию, безопасную работу с персональными идентификаторами,
точную арифметику голосов и схему БД модулей «Реестр домов» и «Доступ и роли». Всё, что здесь сделано, проверяется
тестами без внешних сервисов, кроме одного интеграционного теста с PostgreSQL.

## Что сделано


### Конфигурация (`internal/platform/config`)
Все настройки читаются из переменных окружения. Проверки при старте:
- `DATABASE_URL` обязателен;
- `HMAC_SECRET` не короче 32 байт;
- `MAX_BOT_TOKEN` обязателен, **если не включён `DEV_MODE`**.

Остальное: `HTTP_ADDR` (по умолчанию `:8080`), `INITDATA_MAX_AGE` (по умолчанию `24h`), `SEED_DEMO` (по умолчанию `true`),
`DEMO_INVITE_SLUG`, `LOG_LEVEL`. Эти поля понадобятся в шагах 0.2–0.3.

### Безопасность (`internal/platform/security`)
- `Hasher.Phone` / `Hasher.Account` — HMAC-SHA256 с серверным секретом от нормализованного значения (решение 56).
- `NormalizePhone`: `+7 (900) 123-45-67`, `89001234567`, `79001234567`, `9001234567` → `+79001234567`; остальное — ошибка.
- `NormalizeAccount`: убирает пробелы и разделители, переводит в верхний регистр.
- `NewToken`: 128 бит из `crypto/rand` в base64url, 22 символа `[A-Za-z0-9_-]` (решение 57).

### Пороги ЖК (`internal/rules`)
- `ForTotal(total)` — эталонные значения для дома: 10%, половина, две трети.
- `DemandReached` — **не менее** 10% всех голосов (ст. 45 ч. 6).
- `QuorumReached` — **более** 50% всех голосов (ст. 45 ч. 3).
- `Passed(rule, …)` для трёх правил:
  - `majority_of_participants` — больше половины голосов участников;
  - `more_than_half_of_all` — больше 50% всех голосов;
  - `two_thirds_of_all` — **не менее** 2/3 всех голосов.
- `ParseRule` — проверка правила, прочитанного из БД.

### Площади и веса (`internal/registry/area.go`)
- `ParseAreaCenti("52,30") = 5230` — площадь в целых сотых м², не больше двух знаков после запятой.
- `NewWeight(area, num, den)` — вес = площадь × доля, точная дробь; доля в (0, 1].
- `FormatM2` — округление до 0,01 м² с запятой, **только для показа**.

### Схема БД (`migrations/00001_organizations.sql` — `00009_org_members.sql`)
Таблицы: `organizations`, `houses`, `premises`, `registry_uploads`, `owners`, `owner_records`, `users`, `memberships`, `org_members`.
Соответствуют разделам 1 и 2 документа [04-model-dannyh.md](../04-model-dannyh.md).

## Решения и почему

| Решение | Почему |
|---|---|
| **Площади — целые сотые доли м² (`bigint`), доли — числитель и знаменатель, вес — дробь `weight_num / weight_den`** | Реестр даёт площадь с двумя знаками, а доли бывают 1/3. Десятичная дробь теряет точность, и голос ровно на границе 2/3 мог бы засчитаться неверно (решение 36). Целые числа в БД + `math/big.Rat` в Go дают точный результат. `int64` хватает с запасом: площадь до ~10⁷ сотых × числитель доли |
| **Строгость границ по тексту ЖК:** 10% и 2/3 — «не менее» (≥), кворум и «больше 50%» — «более» (>) | Ошибка в знаке сравнения — ровно тот класс багов, который нельзя увидеть на демо. Каждая граница покрыта тестом «ровно на границе» |
| **Кворум проверяется отдельно от правила большинства** | Кворум — свойство собрания целиком, а не вопроса (решение 16) |
| **UUIDv7 генерирует PostgreSQL 18 (`DEFAULT uuidv7()`), а не Go** | Не нужна отдельная библиотека UUID, id есть у любой строки, вставленной даже вручную через SQL. Цена — требуется PostgreSQL 18, в compose он и будет |
| **В HMAC добавлен префикс вида (`phone:` / `account:`)** | Одинаковые цифры телефона и лицевого счёта не дают одинаковый хеш |
| **Токены — 128 бит в base64url, а не UUID** | UUID не предназначены для токенов доступа (RFC 9562), UUIDv7 раскрывает время создания. Алфавит base64url совпадает с разрешённым в `startapp` MAX (`[A-Za-z0-9_-]`) |
| **Инвариант 9 — частичный уникальный индекс в БД** (`memberships_one_verified_owner`) | Правило «один собственник — одна подтверждённая привязка» держит сама БД, даже при гонке двух запросов |
| **`CHECK ((role = 'owner') = (owner_id IS NOT NULL))`** | Привязка собственника без ссылки на стабильного собственника невозможна, и наоборот |
| **`users` создаётся до `registry_uploads`** | Внешний ключ `registry_uploads.uploaded_by → users` задаётся сразу при создании таблицы |
| **Миграции встроены в бинарник и применяются при старте (goose, `Provider` API)** | Жюри запускает одну команду `docker compose up`, схема поднимается сама. `Provider` не использует глобального состояния goose |
| **`Connect` ждёт БД до 60 секунд** | В compose сервис может стартовать раньше PostgreSQL |
| **Интеграционный тест запускается только при `TEST_DATABASE_URL`** | `go test ./...` работает на любой машине без БД, а полноценная проверка схемы доступна одной командой |
| **Бот в режиме `DEV_MODE` не обязателен** | Локальная разработка и проверка без выданного токена (один токен — один получатель событий) |

## Отклонения от документов

- В [04](../04-model-dannyh.md) вес назывался `weight_m2`, а площадь — `display_area`. В коде это `weight_num / weight_den` (сотые м²) и `display_area_centi`. Документ 04 обновлён под код.
- Коды значений в БД на английском: `uk / tszh / zhsk`, `person / organization / municipality`, `guest / resident / owner`, `phone / account / uk_manual / demo`, `pending / verified / rejected / revoked`.

## Как проверено

```
cd backend
go vet ./...                                   # без замечаний
go test ./...                                  # security, registry, rules — ok; db — skip без БД
docker run --rm -d --name mh-pg-test -e POSTGRES_PASSWORD=test -p 55432:5432 postgres:18-alpine
TEST_DATABASE_URL='postgres://postgres:test@localhost:55432/postgres?sslmode=disable' \
  go test ./internal/platform/db/ -run TestMigrateAndInvariants -v -count=1   # PASS
```

Интеграционный тест проверяет, что:
- миграция применяется, а повторный запуск ничего не делает;
- id имеют формат UUIDv7;
- вторая подтверждённая привязка к тому же собственнику отклоняется;
- привязка собственника без `owner_id` отклоняется.

## Правки по ревью (25.09.2026)

Шаг принят. Внесены важные правки. До первого деплоя исходная `00001` была безопасно переписана и
разделена по правилу «одна таблица — одна миграция»; после первого деплоя схема меняется только новыми миграциями.

| Замечание | Что сделано |
|---|---|
| `houses.current_registry_version` ни на что не ссылается | Составной внешний ключ `(id, current_registry_version) → registry_uploads (house_id, version)`: несуществующую версию БД не примет. Правило «текущей становится только применённая версия» проверяет код, тест появится в 0.2 вместе с сидом. В интеграционный тест добавлена проверка ключа |
| Нет индекса `owners (premise_id)` | Добавлен. При проверке схемы нашлись ещё три пропуска: `memberships (premise_id)`, `memberships (owner_id)` (поиск конфликтов по всем статусам, не только подтверждённым), `houses (org_id)`. Добавлены все |
| Сумма долей помещения ≠ 1 не проверяется | Записано в отчёт загрузки реестра как предупреждение без блокировки: 04, раздел «Загрузка реестра»; 05, этап 2, п. 9 |
| `ParseAreaCenti` принимает знак | Это оказалось не косметикой: `"52.+5"` разбиралось как 52,05 м². Теперь принимаются только цифры, случаи `+52.3`, `52.+5`, `52.-5`, `5 2` добавлены в тест |
| Интеграционный тест должен попасть в CI | Будет в шаге 0.5: команда локального запуска + задача CI с `postgres:18`. Записано в 05, этап 3 |

**Не принято:** проверка первой цифры телефона по набору {3, 4, 5, 6, 9}. Коды 8xx — обычные городские номера (843 — Казань, 812 — Петербург), такое правило отвергло бы номера из реестров УК. Номер, который ни с чем не совпадает, вреда не несёт.

**Ответы на вопросы:** имя модуля оставляем. Версию Go пиним в Dockerfile в шаге 0.5; образ должен быть не ниже `1.27.1`, как в `go.mod`.
