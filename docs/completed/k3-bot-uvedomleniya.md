# К3. Бот-уведомления: требование передано, собрание создано, итог зафиксирован

Дата: 27.09.2026. Статус: готово, ждёт ревью. Ветка: `feat/demand` (некоммичено).

Цель шага (К3 плана до 30.09): замкнуть уведомления пути A. Джобы уже ставятся модулями
в своих транзакциях — теперь воркер бота их обрабатывает и рассылает сообщения в MAX.

## Что сделано

```
backend/
  internal/bot/notify_demand.go     demand_delivered → сотрудникам УК (в демо — инициатору)
  internal/bot/notify_meeting.go    meeting_created → собственникам; meeting_finalized → итог
  internal/demand/announce.go       Announce: факты требования для уведомления
  internal/meeting/announce.go      BotView: карточка собрания для системных уведомлений
  cmd/app/main.go                   регистрация трёх хендлеров в воркере
```

### demand_delivered → сотрудникам УК

- Джоба ставится в транзакции передачи требования (Д1, решение плана: «принято — значит разослано»).
- Получатели: `access.StaffRecipients(houseID, initiatorUserID)` — в обычном доме сотрудники УК,
  в демо-доме только инициатор (решение 79: жюри не получает чужих требований).
- Текст: «Поступило требование…: „Камеры“, поддержка 317,50 м² из 300,00 м² (10% площади дома),
  срок ответа УК — 45 дней (до 12.11.2026)».

### meeting_created → собственникам дома

- Джоба от создания собрания. Получатели: `VerifiedOwnerRecipients(houseID)` + инициатор
  (дедупликация по MAX id).
- Текст: «Назначено собрание по „…“ (дом). Голосование: 03.10 15:04 — 10.10 15:04. Повестка: 2 вопрос(ов).
  Отметь свой бюллетень в приложении» + пометка демо-дома.

### meeting_finalized → инициатору и собственникам

- Текст: «Итог собрания …: собрание состоялось. Решения по вопросам: • Избрать председателя… — ПРИНЯТО
  (2000 м² „за“…)», исход («состоялось / нет кворума») и «протокол сформирован и доступен в приложении».

## Решения и почему

| Решение | Почему |
|---|---|
| **Получатели собрания — `VerifiedOwnerRecipients`, дедуп по MAX id** | Собрание касается всех подтверждённых собственников; инициатор — подтверждённый собственник (docs/01), поэтому отдельная доставка не нужна |
| **`access.ManagesAsStaff` / `StaffRecipients` — единственные точки решений 79** | Изоляция демо-сотрудников живёт в доступе, бот и модули не дублируют правило |
| **Хендлеры — структуры с интерфейсами модулей** | Тестируются с фейками без сети; `Messages` — тот же интерфейс, что у PollInviter |
| **Важные события без тихих часов** | Решение 29: старт собрания и итог приходят всегда |

## Как проверено

- Юнит-тесты хендлеров: текст, адресаты (MAX id), отказ при пустом payload.
- Интеграционный тест флоу требования: джоба `demand_delivered` создаётся в той же транзакции,
  что и передача (Д1), дедуп-ключ один на требование.
- Полный набор с `-race` на PostgreSQL 18 — зелёный; `gofmt`/`vet` чисто.

- `PATCH /me` (название и аватар бота) — ждёт решения по названию продукта.
