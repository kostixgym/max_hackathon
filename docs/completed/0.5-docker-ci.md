# Шаг 0.5. Docker Compose, Caddy, CI, README

Дата: 25.09.2026. Статус: готово, ждёт ревью. Ветка: `chore/docker-ci`.

Цель шага — выполнить обязательные требования методички к сдаче (с. 9): запуск всех компонентов одной командой, `Dockerfile`,
`compose.yaml`, `.dockerignore`, `.env.example` без секретов, сборка не дольше 5 минут, README по чек-листу. Плюс CI, чтобы
интеграционные тесты схемы выполнялись у всех, а не только на одной машине (ревью 0.1).

## Что сделано

```
compose.yaml                   db (PostgreSQL 18) + app (Go) + web (Caddy), одна команда запуска
backend/Dockerfile             многоэтапная сборка: golang:1.27-alpine → distroless/static, не root
deploy/web.Dockerfile          Caddy + статика (до 0.4 — заглушка)
deploy/Caddyfile               единственный вход: /api/* → app, остальное — статика; HTTPS на сервере автоматически
deploy/placeholder/index.html  временная страница: показывает, доступен ли API
.dockerignore                  в образы не попадают .git, docs, .env, node_modules
.env.example                   переменные compose и приложения, без секретов
.github/workflows/ci.yml       gofmt, go vet, все тесты с PostgreSQL 18, сборка образов с лимитом 5 минут
backend/cmd/app/main.go        команда `app healthcheck` для проверки здоровья контейнера
README.md                      по чек-листу методички
```

## Решения и почему

| Решение | Почему |
|---|---|
| **Caddy — единственный вход, `app` и `db` наружу не публикуются** | Одна точка для HTTPS и статики, база недоступна снаружи даже при ошибке настройки файрвола. Мини-приложение и API на одном домене — CORS не нужен |
| **HTTPS через `SITE_ADDRESS`:** `:80` локально, домен на сервере | Caddy сам получает сертификат Let's Encrypt. Мини-приложение в MAX работает только по HTTPS, а локально жюри удобнее HTTP |
| **Итоговый образ бэкенда — distroless, пользователь не root** | Нет shell и пакетного менеджера — меньше поверхность атаки. Поэтому проверку здоровья выполняет сам бинарник: `app healthcheck` запрашивает `/api/v1/readyz` |
| **Контекст сборки — корень репозитория, один `.dockerignore`** | Требование методички — `.dockerignore` в репозитории. Один файл на все образы; `docs` и `.env` в контекст не попадают |
| **Слой зависимостей Go отдельно** (`go.mod`/`go.sum` → `go mod download` → код) | Пока зависимости не меняются, пересборка после правки кода не качает модули заново |
| **Go 1.27 закреплён в Dockerfile** (`golang:1.27-alpine` = 1.27.1, как в `go.mod`) | Ответ на вопрос ревью 0.1 |
| **`app` стартует после здоровой `db`, `web` — после здорового `app`** | Жюри не увидит 502 в первые секунды после запуска |
| **Том PostgreSQL монтируется в `/var/lib/postgresql`** | В образах PostgreSQL 18 данные лежат в `/var/lib/postgresql/18/…`; монтирование родительского каталога — рекомендация образа |
| **`DEV_MODE=false` по умолчанию в `.env.example`** (было `true`) | Пример копируют как есть, в том числе на сервер. Режим разработки включается явно, README объясняет, когда |
| **`POSTGRES_PASSWORD` обязателен** (`${POSTGRES_PASSWORD:?…}`) | Без него compose сразу скажет, что заполнить, а не упадёт непонятной ошибкой подключения |
| **`env_file` с `required: false`** | `docker compose config` и сборка работают и без `.env` (например, в CI); значения по умолчанию безопасные |
| **CI: интеграционные тесты с сервисом `postgres:18`** | Единственные тесты схемы и прав доступа не должны зависеть от того, у кого есть Docker (ревью 0.1, п. 6) |
| **CI: базовые образы скачиваются отдельным шагом, сборка — с `timeout 300`** | Методичка считает 5 минут без первоначальной загрузки базовых образов — так и меряем |
| **Мини-приложение — заглушка с проверкой API** | Шаг 0.4 ещё не сделан, но цепочка «Caddy → статика + API» уже проверяется. В `deploy/web.Dockerfile` записано, как заменить заглушку сборкой `miniapp/` |

## Как проверено

- **Сборка с нуля** (`docker compose build --no-cache`, базовые образы скачаны заранее): **12 секунд** при лимите 300.
- **`docker compose up`:** `db` и `app` в состоянии `healthy`, `web` запущен. Через `http://localhost:8080`:
  - `/api/v1/healthz` → `{"status":"ok"}`, `/api/v1/readyz` → `{"status":"ready"}`;
  - `/api/v1/me` без подписи → `401`, с `X-Dev-User-Id` и ссылкой демо-дома → сводка дома с порогами 3000 / 300 / 1500 / 2000;
  - `/` → страница-заглушка, заголовки `X-Content-Type-Options` и `Referrer-Policy` на месте, заголовка `Server` нет;
  - порт PostgreSQL наружу не опубликован.
- **`stop` → `up`:** демо-дом один, с той же ссылкой; **`down`:** тома сохраняются.
- `docker compose config -q` — без ошибок; `compose.yaml` и `ci.yml` — валидный YAML.
- `go vet`, `gofmt`, все Go-тесты — зелёные.
- **CI на GitHub запустится на первом PR** этой ветки: локально его не прогнать.
