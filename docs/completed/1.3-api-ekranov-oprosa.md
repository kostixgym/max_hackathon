# Шаг 1.3, бэкенд. API экранов опроса: шаблоны, форма, список и карточка инициативы

Дата: 26.09.2026. Статус: готово, ждёт ревью. Ветка: `feat/initiative-read-api`.

Экраны шага 1.3 — выбор шаблона, создание инициативы, карточка с прогрессом и голосом — строятся на ручках контракта
[API_DESCRIPTION.md](../API_DESCRIPTION.md), которых не было. Эта часть шага делает их. Экраны — работа участника 3.

## Что сделано

| Ручка | Что возвращает |
|---|---|
| `GET /templates` | последние версии шаблонов: код, название, версия, описание |
| `GET /templates/{code}` | форму шаблона (`params_schema` + `ui_schema`), повестку с правилами большинства и ссылками на ЖК |
| `GET /houses/{houseID}/initiatives` | инициативы дома, новые сверху, не больше 100 |
| `GET /initiatives/{id}` | карточку: поля и значения формы, повестку, пороги от снимка реестра, голос пользователя, `allowed_actions` |

### Форма шаблона

- **Шаблон «Видеонаблюдение» получил форму.** Раньше схема была пустой, и `params` сохранялись как есть. Поля такие,
  как задумано в плане (docs/00, шаг 1): где ставим, сколько камер, ориентир по стоимости, способ оплаты, кто имеет
  доступ к записям. Обязательны количество камер и способ оплаты, как в контракте.
- **Сервер проверяет `params` по схеме** при создании инициативы. Ошибка приходит как `400 invalid_params` с полем
  `error.field` и готовым текстом для пользователя, например: Поле «Количество камер»: значение не больше 1000.
- **Схема ограничена тем, что умеет показать мини-приложение:** плоские поля `string`, `integer`, `number`, `boolean`
  с `enum`, `required`, `minimum`, `maximum`, `minLength`, `maxLength`. Шаблон с другими ключевыми словами не загрузится при
  старте, так что поле, которое фронтенд не умеет рисовать, до пользователя не дойдёт. Свободный текст обязан иметь
  `maxLength`.
- **`ui_schema`** задаёт порядок полей, вид (`textarea`, `select`) и подписи значений `enum`. Тест проверяет, что каждое
  поле есть в порядке и у каждого значения `enum` есть подпись.

### Карточка и действия

- **`allowed_actions` содержит все семь действий контракта.** Работают правила двух действий:
  - `start_poll` — инициатор, черновик;
  - `cast_poll_vote` — идёт опрос, пользователь — подтверждённый собственник.
- **Эти правила общие для карточки и для самих ручек.** `StartPoll` вызывает то же правило, что и карточка. Голос
  проверяет модуль опроса по тем же условиям.
- **Остальные действия приходят с причиной `not_implemented`**: правка, пути A и B, собрание, отмена. Их ручки
  появятся в шагах 1.4–1.6. Шаг заменит `not_implemented` правилом, и кнопка на фронтенде включится без правок.
- **`my_vote`** — голос пользователя: выбор, вес в м² (сумма по всем квартирам), анкета. `null`, если не голосовал.

### Видимость черновика (новое решение 76 в 04)

Черновик видят только его инициатор и автор, соседи видят инициативу с запуска опроса. Чужой черновик для API не
существует: `404` в карточке и в прогрессе, в списке его нет. До запуска текст ещё меняется, а в демо-доме список
иначе заполнили бы черновики всех тестировщиков.

### Найдено по ходу и исправлено

- **`MayViewInitiatives` с неверным id дома возвращал бы 500.** Раньше id дома туда приходил только из базы, а в
  `GET /houses/{houseID}/initiatives` он приходит из URL. Теперь неверный id — «нет такого дома», то есть `403`.

## Решения и почему

| Решение | Почему |
|---|---|
| **Свой проверяльщик подмножества JSON Schema**, а не полная библиотека | Фронтенд поддерживает только подмножество, и сервер должен отказывать ровно в том же. Библиотека приняла бы схему, которую мини-приложение не покажет. Плюс своя проверка отдаёт имя поля и причину для текста ошибки. Кода — около 300 строк с комментариями, новых зависимостей нет |
| **Числа проверяются как `float64`**, а не точными дробями | Точная дробь из `1e999999999` раскрылась бы в мегабайты. Для полей формы (количество, рубли) `float64` точен. Тест проверяет, что такие числа отклоняются быстро. Площади и веса голосов по-прежнему считаются точно |
| **Действия шагов 1.4–1.6 — `not_implemented`**, а не будущие правила | Будущие правила зависят от ролей УК и собрания, которых ещё нет. Угаданное правило включило бы кнопку, за которой нет ручки |
| **Голос в карточке ищется по тому, кто голосовал** (`user_id`), а не по текущей привязке к собственнику | Голос засчитан и после смены привязки. Если искать по привязке, пользователь видел бы «не голосовал», а его голос продолжал бы считаться |
| **v1 шаблона обновлена на месте**, а не выпущена v2 | До запуска инициатив с v1 нет, кроме тестовых. После запуска изменение шаблона — новая версия (комментарий в `rules/templates.go`) |
| **Гостю — `403`**, хотя решение 19 разрешает показать ему название | Для сценария этапа 1 не нужно: мини-приложение сначала предлагает подтвердить квартиру. Добавим вместе с привязкой через `/memberships` |

## Как пользоваться на фронтенде

1. `GET /me` — дом из ссылки (`house.id`) и привязки пользователя. Нет подтверждённой привязки — экран подтверждения
   (в демо-доме `POST /houses/{slug}/demo-membership`).
2. Список: `GET /houses/{houseID}/initiatives`.
3. Создание:
   1. `GET /templates` — выбор шаблона.
   2. `GET /templates/{code}` — форма по `params_schema` и `ui_schema`, повестка с большинством по каждому вопросу.
   3. `POST /houses/{houseID}/initiatives`.
4. Карточка: `GET /initiatives/{id}`. Кнопки — по `allowed_actions`. Запуск опроса — `start-poll`, голос с анкетой —
   `PUT my-vote`, прогресс — `GET /initiatives/{id}/poll`.

## Как проверено

- `gofmt`, `go vet`, все тесты с `-race` на PostgreSQL 18. Интеграционный тест два раза подряд на одной базе.
- **Новые тесты:**
  - проверка формы: допустимые значения, каждая причина ошибки, длина в символах, а не в байтах, огромные числа;
  - схемы вне подмножества не компилируются (27 случаев);
  - согласованность шаблонов: схема, `ui_schema`, повестка, типы решений;
  - `allowed_actions` для инициатора, соседа-собственника и жителя на разных стадиях;
  - HTTP: шаблоны, список, карточка, чужой черновик — `404`, не член дома — `403`, `invalid_params` с полем;
  - интеграция:
    - `params` без обязательного поля отклоняются;
    - черновик виден только инициатору, после запуска опроса — соседям;
    - карточка из базы: повестка, шаблон, снимок;
    - «мой голос» с суммой по двум квартирам;
    - шаблон по id и список шаблонов.
- **Мутационная проверка.** Тесты падают, если сломать любое из правил:
  - скрытие черновика в списке и в карточке;
  - проверку собственника для голоса;
  - стадию для запуска опроса;
  - обязательные поля и неизвестные поля;
  - дробное число в целом поле;
  - длину в байтах вместо символов;
  - сумму весов в «моём голосе»;
  - проверку `params` при создании;
  - неверный id дома.
- **Смоук собранного бинарника** на базе со старой пустой схемой шаблона:
  - при старте схема обновилась;
  - ошибки формы: без полей, 5000 камер, лишнее поле, чужое значение `enum`, `params` не объект;
  - создание, список и карточка у инициатора и соседа до и после запуска опроса;
  - голос соседа с анкетой в карточке;
  - посторонний получает `403`, неверные id — `403` и `404`;
  - ошибок в журнале нет.

## Что не сделано

- Название инициативы для гостя (решение 19) — вместе с `/memberships`.
- `GET /templates/{code}?version=` — понадобится, когда у шаблона появится вторая версия. Сейчас карточка отдаёт
  `template.version`, а форма берётся из последней версии.
- Пагинация списка дальше 100 инициатив.
- Опрос не закрывается сам по окончании срока, это отдельная доработка (итог опроса по `poll_ends_at`).
